Scope
-----
Both layers: the oracle (src/) and the isolated lending market (src/market/).
The `--no-match-coverage` filter excludes the test helpers and the deployment
scripts, which are not shipped code.

Read this before quoting a number
---------------------------------
This file previously held a phase-1-only run that reported 100% branch coverage.
That figure was true of what it measured and false of this repository: it was
taken before the market layer existed. Branch coverage across both layers was
73.63% at that point, with `CotejoMarket.sol` — the contract that holds the
money — at 59.34%.

Branch coverage is the number quoted here because it is the one that is hard to
move. Line coverage and function coverage are both higher and both easier to
inflate, so quoting either alone would be selective.

The five branches that are not covered
--------------------------------------
Not "not yet". Each of these was traced and is unreachable from any caller, and
listing them is more useful than a percentage that rounds them away. None is
load-bearing; all five are defence-in-depth behind a guard that fires earlier.

  PriceRouter.sol:154          `if (n == 0) lowestUsd = 0;`
      `n` is the fresh-source count, and this line runs only after INV-1 passed,
      which requires `n >= route.minSources`. `minSources == 0` is rejected at
      route validation (PriceRouter.sol:350), so `n >= 1` here always.

  CotejoMarket.sol:631         `if (v.repaidShares > pos.borrowShares) ...`
      The close-factor check above it bounds `repaidAssets` by `debtAssets`, and
      the shares conversion rounds down, so the result cannot exceed the shares
      the position holds.

  CotejoMarket.sol:773         `if (w.seized > pos.collateral) ...`
      The degraded wind-down seizes pro-rata plus a premium, bounded by
      `CLOSE_FACTOR` (50%) and `DEGRADED_PREMIUM_MAX_BPS` (10%). The worst case
      is 55% of the collateral. It would become reachable if `CLOSE_FACTOR` were
      ever raised above ~90.9%, which is why the clamp stays.

  CotejoMarket.sol:915         `if (loanPrice == 0) revert Market__DepthUnavailable`
      `_capFromDepth` runs inside `borrow`, after `_observeOracle` succeeded.
      That required `CotejoOracleAdapter.price()` to succeed, which reverts on
      exactly the same zero. Same quantity, checked twice.

  CotejoOracleAdapter.sol:92   `if (loanWad == 0) revert Market__InvalidParameter`
      `PriceRouter.latestPrice` always reports at `ROUTER_DECIMALS = 18`, so the
      adapter's `_toWad` is the identity and cannot truncate. A zero would have
      to come from the router itself, which drops zero-priced sources
      (PriceRouter.sol:259) and refuses a downscale that would annihilate a
      value (AggregationLib.sol:126, `Cotejo__PrecisionLoss`). Defence against a
      future change to `ROUTER_DECIMALS`, not against anything reachable today.

`TwapSource.sol` shows 72.73% on lines and 100% on branches because it is a
skeleton that always reverts by design; there is nothing behind the revert to
reach.
